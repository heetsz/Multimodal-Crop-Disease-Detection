\begin{abstract}
Automated grapevine disease recognition is commonly treated as an image-classification problem, although disease development is also influenced by environmental conditions. This paper evaluates whether weather variables provide useful complementary information when paired with grapevine leaf images. We use the GVLiD dataset containing 3,477 images from four classes: Black Rot, Esca, Healthy, and Leaf Blight. Image records are paired with temperature, humidity, and rainfall features obtained from a location- and date-based weather pipeline. We first compare image-only, weather-only, and simple image--weather baselines, and then evaluate ConvNeXt-Tiny models using image-only, concatenation, late-fusion, FiLM, and gated-fusion heads with a seven-day weather window. In the recorded test results, the gated-fusion model reaches 85.47\% accuracy and 0.799 macro-F1, compared with 81.35\% accuracy and 0.743 macro-F1 for the corresponding image-only model. The weather-only baseline reaches 34.71\% accuracy and 0.201 macro-F1. These results indicate that weather features may provide complementary signal, but they should not be interpreted as definitive evidence of broad temporal generalization. The dataset contains substantial duplicate files, label disagreements between folder names and metadata, a single capture date, and only two weather-grid points. Consequently, the current findings are best viewed as an empirical multimodal benchmark requiring stricter duplicate- and group-aware validation before deployment or strong causal claims.
\end{abstract}

\section{Introduction}
Grapevine diseases can reduce yield and quality, while visual diagnosis from leaf photographs is affected by disease similarity, lighting, background, and symptom variability. Transfer-learning models provide a practical approach to automated classification, but an image-only model does not observe environmental context that may be related to disease development.

This work studies whether weather features can complement visual evidence for grapevine leaf disease classification. The research question is deliberately empirical:
\begin{quote}
Does adding location- and date-associated temperature, humidity, and rainfall improve classification over an image-only model under the same experimental protocol?
\end{quote}

The contribution is an experimental comparison rather than a claim of a new universally superior architecture. We report image-only and weather-only baselines, multimodal fusion strategies, class-level metrics, and limitations identified during dataset auditing. In particular, the study makes the duplicate and metadata risks visible instead of presenting the current split as fully leakage-free.

\section{Related Work}
Plant disease recognition has used convolutional networks such as ResNet, VGG, MobileNet, and EfficientNet, as well as transformer-based models. Modern backbones can achieve high scores on curated datasets, but accuracy is strongly affected by class definitions, duplicate images, background similarity, and the choice of train--test split. Environmental variables have biological relevance, yet their value depends on accurate spatial and temporal pairing. Therefore, multimodal studies require ablations against image-only and weather-only baselines and must report whether data groups can cross partition boundaries.

\section{Dataset and Data Audit}
\subsection{GVLiD Dataset}
The project uses the GVLiD grapevine leaf disease dataset. It contains 3,477 image files grouped into four classes: Black Rot (808 images by folder label), Esca (888), Healthy (1,109), and Leaf Blight (672). The dataset metadata contains 3,477 records, 28 vineyard identifiers, GPS coordinates, capture information, and categorical weather-related fields.

The folder-derived class label was used for the recorded experiments because the audit found 1,344 rows where the metadata disease field disagreed with the folder label. This choice is a practical convention, not proof that every folder label is correct.

\subsection{Quality Risks}
The audit identified 446 exact-duplicate hash groups and 1,068 duplicate files beyond the first copy. Two duplicate groups cross class labels. All records have the same capture date, 2023-06-15, and the weather pipeline uses two weather-grid points. These facts limit the strength of temporal and geographic generalization claims.

The Phase 2 manifest contains 2,245 training rows, 578 validation rows, and 654 test rows. It reports 1,514 duplicate rows and 1,344 metadata--folder label mismatches. The current results should therefore be treated as results for the recorded split, not as a final leakage-safe estimate. A definitive follow-up evaluation should deduplicate first and split by duplicate group and vineyard.

\subsection{Weather Pairing}
The weather pipeline associates image records with external weather features using capture date and geographic metadata. The evaluated multimodal experiments use temperature, humidity, and rainfall summarized over a seven-day window ending on the recorded capture date. Temperature and humidity are represented as continuous features and rainfall is aggregated as a numeric weather variable. Because all images share one capture date, the seven-day feature is a historical window around one date rather than evidence across multiple seasons.

\section{Experimental Method}
\subsection{Preprocessing}
Images are resized and normalized for transfer learning. The weather variables are standardized using training-set statistics. The Phase 3 baseline experiments use MobileNetV2 for the visual branch and an MLP for the weather-only branch. Phase 4 uses ConvNeXt-Tiny for the visual branch and compares several fusion heads. Models are selected using validation performance and evaluated on the recorded test partition.

\subsection{Models}
The baseline models are:
\begin{enumerate}
    \item MobileNetV2 using images only;
    \item a weather-only MLP using temperature, humidity, and rainfall; and
    \item MobileNetV2 with weather features concatenated with the visual representation.
\end{enumerate}

The Phase 4 ConvNeXt-Tiny comparison evaluates an image-only head and four multimodal strategies:
\begin{itemize}
    \item \textbf{Concatenation:} image and weather embeddings are concatenated before classification;
    \item \textbf{Late fusion:} image and weather predictions are combined after separate prediction heads;
    \item \textbf{FiLM:} weather features condition visual features through feature-wise modulation;
    \item \textbf{Gated fusion:} a learned gate controls the contribution of the weather embedding.
\end{itemize}

\subsection{Metrics}
We report accuracy, macro-precision, macro-recall, and macro-F1. Macro-F1 is emphasized because the four classes are not equally represented. All values in the following tables are taken from the generated Phase 3 and Phase 4 result files.

\section{Discussion}
The results support a cautious interpretation: weather features can be useful as auxiliary input in this dataset and may improve macro-F1 when combined with a sufficiently strong visual backbone and an appropriate fusion head. The weak weather-only result indicates that the image remains the primary information source. The different Phase 3 and Phase 4 outcomes also show that the effect is architecture-dependent; weather did not improve MobileNetV2 accuracy in the recorded baseline run, while gated ConvNeXt fusion improved both accuracy and macro-F1.

The result should not be compared directly with 99\% scores from other papers or model implementations. Such scores may use different datasets, class distributions, duplicate policies, or test partitions. A fair comparison requires reproducing the same split and preprocessing protocol.

\section{Limitations and Required Validation}
\begin{enumerate}
    \item \textbf{Duplicate risk:} The current manifest contains many duplicate rows. Exact and near-duplicate groups must be kept within a single partition before treating the test score as a generalization estimate.
    \item \textbf{Group generalization:} A future split should hold out vineyards, or at least duplicate groups and vineyards jointly, to test whether the model recognizes disease rather than capture-specific appearance.
    \item \textbf{Single capture date:} All records use 2023-06-15. The seven-day weather experiment therefore does not establish generalization across seasons or disease-development timelines.
    \item \textbf{Sparse weather coverage:} Only two weather-grid points are represented, so microclimate variation is not evaluated.
    \item \textbf{Label disagreement:} Folder and metadata labels disagree for 1,344 records. The label policy should be manually audited or independently verified.
    \item \textbf{Statistical validation:} The current tables are single recorded runs for the listed configurations. At least three seeds on the same strict split, confidence intervals, and paired comparisons are needed before claiming a reliable improvement.
    \item \textbf{External validation:} An independent vineyard, date, camera, or region is needed to assess field robustness.
\end{enumerate}

\section{Conclusion}
This study presents a reproducible starting point for evaluating weather-aware multimodal grapevine disease classification. On the current GVLiD split, ConvNeXt-Tiny with gated seven-day weather fusion achieves 85.47\% accuracy and 0.799 macro-F1, compared with 81.35\% accuracy and 0.743 macro-F1 for the image-only counterpart. The improvement is promising, but it is not sufficient by itself to establish broad scientific or deployment claims because the dataset contains duplicate files, label disagreements, a single capture date, and limited weather-grid diversity.

The next decisive experiment is a deduplicated, vineyard-aware split followed by repeated-seed comparison of the strongest image-only and multimodal models. If the multimodal improvement persists under that protocol and on independent data, the evidence for a useful weather contribution will be substantially stronger. If it disappears, the result will still provide a useful negative finding about the limits of weather augmentation for this dataset.
